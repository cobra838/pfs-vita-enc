# PS Vita PFS: расшифровка и обратное шифрование

[English](README.md) | Русский

`pfs.py` работает непосредственно с игровым **метаданными PFS** (`sce_pfs/unicv.db`, `sce_pfs/files.db`) и **лицензией** (`sce_sys/package/work.bin`).

```bash
# Установка зависимостей
python -m pip install -r requirements.txt
```

## Директория


```bash
# Расшифровка директории encrypted_game с копированием в encrypted_game
python pfs.py decrypt encrypted_game decrypted_game

# Зашифровка директории decrypted_game с копированием в rebuilt_game, если метаданные PFS и лицензия внутри decrypted_game
python pfs.py encrypt decrypted_game rebuilt_game

# Зашифровка директории decrypted_game с копированием в rebuilt_game, если метаданные PFS и лицензия отдельно
python pfs.py encrypt decrypted_game rebuilt_game --sce-pfs saved/sce_pfs --license saved/work.bin
```

## Один файл

Входной файл может лежать **где угодно**. Для отдельного файла укажите оба пути:  
`--sce-pfs` — папка с `files.db` и `unicv.db`  
`--license` — файл `work.bin` или `.rif`  
`--path` — относительный путь файла, записанный в files.db, обычно соответствует пути распакованных файлов. Это не путь к входной или выходному файлу.

```bash
# Расшифровка входного файла encrypted_icon.png в icon.png и относительным путем sysdata/icon.png для files.db, если метаданные PFS и лицензия отдельно
python pfs.py decrypt encrypted_icon.png icon.png --sce-pfs saved/sce_pfs --license saved/work.bin --path sysdata/icon.png
```

Для обратного шифрования одиночного файла используются те же метаданные и лицензия:

```bash
python pfs.py encrypt icon.png encrypted_icon_new.png --sce-pfs saved/sce_pfs --license saved/work.bin --path sysdata/icon.png
```

В этом примере команда `encrypt` создает `encrypted_icon_new.png` — зашифрованную версию входного `icon.png`. Также она создает `encrypted_icon_new.png.unicv.db` — полный `unicv.db` с пересчитанными подписями для этого файла.  
В режиме одного файла скрипт сверяет размер входного файла с записью в переданном `files.db`. Если используется исходный `sce_pfs`, зашифровать измененный по размеру файл этим режимом нельзя; для этого используйте шифрование папки.  
Для повторной расшифровки скрипт автоматически подхватит соседний `.unicv.db`; другой путь можно задать через `--unicv`.

## Особенности

Если имя файла уникально среди файлов игры, можно опустить `--path`.  
Если есть несколько `icon.png`, то конкретный путь задается так: `--path sysdata/icon.png`.

При работе с директорией `--sce-pfs` и `--license` можно не указывать: скрипт сам ищет `sce_pfs` и `sce_sys\package\work.bin` внутри входной папки. Расшифровка копирует их в выходной результат, поэтому эту папку можно затем зашифровать обратно без исходной зашифрованной папки. Если метаданные или лицензия лежат отдельно, задайте их пути через `--sce-pfs` и `--license`.

`sce_pfs` содержит метаданные, а не содержимое игровых файлов. При обработке папки скрипт проходит файлы из `files.db`: отмеченные как зашифрованные шифрует, остальные копирует без шифрования. Если отдельного файла нет в `files.db`, скрипт завершится ошибкой. При шифровании папки он обновляет размеры существующих файлов в выходном `files.db`, число секторов и подписи в выходном `unicv.db`, а также записи в `pflist`, если он есть. Исходные папки не меняются; выходная папка должна быть новой.

## Ограничение обратной операции шифрования

Все файлы, перечисленные в исходном PFS, должны оставаться на тех же относительных путях.  
Добавление и удаление файлов не поддерживается.  
Изменение размера поддерживается при шифровании **папки**. При шифровании одного файла с исходным `sce_pfs` изменить его размер нельзя.  
Поддерживается игровой PFS с `unicv.db`, `image_spec=1`, `key_id=0`. Другие варианты завершаются ошибкой.
